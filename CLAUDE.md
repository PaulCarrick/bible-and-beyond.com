# Bible and Beyond

A web app that answers Bible questions using AI/ML.

## Architecture
- `drupal/` — Drupal 11 (PHP), run with DDEV. Content management and admin. Exposes content via JSON:API.
- `ml-service/` — Python 3.12 + FastAPI. AI/ML logic and the question-answering API.
- `frontend/` — React + TypeScript + Vite. The public web UI; calls ml-service and Drupal.

## Local URLs
- Drupal: https://bible-and-beyond.ddev.site
- ML service: http://localhost:8000 (API docs at /docs)
- Frontend: http://localhost:5173
- Live site: https://bible-and-beyond.com (app) and https://cms.bible-and-beyond.com (Drupal); see "Production server" below

## Running locally
- Drupal: `cd drupal && ddev start` (use `ddev composer` and `ddev drush`, never local php/composer)
- ML service: `cd ml-service && source .venv/bin/activate && uvicorn main:app --reload --port 8000`
- Frontend: `cd frontend && npm run dev`
- If something else already uses port 8000 (Docker sometimes does), run uvicorn on 8001 and put `VITE_ML_SERVICE_URL=http://localhost:8001` in `frontend/.env.local` (git-ignored).

## Conventions
- No abbreviations in variable, function, or method names.
- 2-space indentation in PHP, TypeScript, JSON, YAML; follow the formatter's default for Python.
- Keep solutions simple and direct; avoid unnecessary abstractions.
- Show complete files/functions when making changes.
- Never commit secrets; use `.env` files (gitignored) and keep a `.env.example`.

## Testing
- Python: pytest — `cd ml-service && source .venv/bin/activate && python -m pytest`
- Frontend: Vitest (to be added)
- Drupal: PHPUnit via `ddev exec vendor/bin/phpunit` (to be added)
## Bible database
- Postgres 17 + pgvector in Docker (`docker compose up -d` from the repo root), container `bible-and-beyond-database`, host port 5434.
- Connection string lives in `ml-service/.env` as `DATABASE_URL` (never commit `.env`).
- Schema: `ml-service/database/schema.sql` — tables `translations`, `books` (canonical 1–66 with USFM codes and name aliases), `verses`, `verse_embeddings`. Applying it drops and recreates these tables.
- Import a translation (BSB tab format or eBible `*_vpl.txt` format): `.venv/bin/python scripts/import_bible.py data/<file>.txt --code BSB --name "Berean Standard Bible" --license "Public domain"`. KJV also needs `--strip-brackets`.
- Search in public-domain text (BSB); copyrighted translations like ESV are only fetched for display, never stored.
- Each translation has an `is_published` flag. Search and the Bible picker only see published ones. Database changes live in `ml-service/database/migrations/` as files that are safe to run twice; `deploy/deploy.sh` applies them. `schema.sql` is kept in step for fresh databases.
- The importer lives in `ml-service/bible_import/`; `scripts/import_bible.py` (command line, publishes at once unless `--unpublished`) and `scripts/manage_bibles.py` (JSON output, used by Drupal) both call it.

## Licensed Bibles (API.Bible)
- NIV, NASB 2020 and The Message come from API.Bible (free Starter plan: non-commercial only, 5,000 requests a month). Code is in `ml-service/api_bible.py`; the key and endpoint are `API_BIBLE_KEY` and `API_BIBLE_ENDPOINT` in `ml-service/.env`.
- Their text is never stored in our database; it is fetched on demand and cached in memory (search results 10 minutes, copyright metadata 24 hours; the terms require refreshing within 30 days).
- Terms to keep: show each Bible's copyright notice with its text, keep the visible API.Bible link and "Bible copyright notices" page, and report every view to FUMS (`frontend/src/fums.ts`). Never alter the text, never use it commercially, and never put it in AI prompts or training data. Use only the public-domain local Bibles (ASV, BSB, KJV, WEB) for `/ask`.
- These Bibles are searched one at a time, matching all words, in Bible order. Match any, exact phrase, whole words, per-book counts and sorting by contents are not available for them.
- Backend tests fake the API so they do not use the monthly allowance. Live calls count against it, so keep them few.

## Production server
- One AWS Lightsail instance (Debian 13, 2 vCPU, about 2 GB RAM plus a 2 GB swap file), static IP `54.200.249.10`. Firewall: ufw and the Lightsail firewall allow only ports 22, 80 and 443.
- Access: `ssh bible-and-beyond` (an entry in `~/.ssh/config`; user `paul`, key login only, password login is off). The repository lives at `/home/paul/bible-and-beyond.com` and everything runs as `paul`. `paul`'s sudo asks for a password; system-level setup was done through the Lightsail default `admin` account, whose key is kept outside the repository.
- Layout: nginx serves `frontend/dist` and proxies `/api/` to the ML service (systemd user service `bible-and-beyond-ml`, 127.0.0.1:8000, Python 3.13). PostgreSQL 17 + pgvector runs natively (database `bibleandbeyond`, socket login as `paul`, no password). Drupal runs through a PHP-FPM pool as `paul` with MariaDB 11.8 (database `bibleandbeyond_drupal`, socket login).
- Secrets exist only on the server and are never committed (this repository is public): `ml-service/.env` (mode 600), `drupal/web/sites/default/settings.local.php` (git-ignored; template in `deploy/drupal/settings.local.php.example`), and the TLS private keys in `/etc/ssl/private` (root only).
- Rate limits live in nginx (`deploy/nginx/bible-and-beyond-limits.conf`): the API allows about 5 requests a second per visitor, searches in the licensed Bibles 20 a minute, and Drupal's login page 10 a minute. The ML service also stops calling API.Bible at 4,500 requests a month (`API_BIBLE_MONTHLY_LIMIT`; the count is kept in `ml-service/data/api_bible_usage.json`).
- Drupal: it was installed fresh, not imported from DDEV. Nothing in the app calls it yet. For a one-time admin login link: `ssh bible-and-beyond 'cd ~/bible-and-beyond.com/drupal && vendor/bin/drush user:login --name=admin --uri=https://cms.bible-and-beyond.com'`. Drupal keeps `sites/default` read-only on purpose.

## Managing Bibles from Drupal
- Drupal is the admin screen for the main site; the Bible text goes into the main PostgreSQL database, never into Drupal's. Page: https://cms.bible-and-beyond.com/admin/bibles (Drupal module `drupal/web/modules/custom/bible_admin`).
- Flow: upload a `.txt` file with a code, name, language and license; see a preview (format, verse and book counts, sample verses, warnings); confirm to import. A new Bible is **hidden until published** (Publish / Hide / Delete on the list page). Re-importing an existing code replaces its text and keeps its published state. The last published Bible cannot be hidden or deleted. The codes NIV, NASB and MSG are refused (they belong to API.Bible).
- Drupal runs `ml-service/scripts/manage_bibles.py` with a fixed argument list (no shell). The uploaded file is kept in `/home/paul/drupal-private/bible-uploads/` only until the import is confirmed or cancelled, and stale ones are removed by cron after a day. Check the Drupal log (type `bible_admin`) to see who imported, published or deleted what.
- Roles: `administrator` (everything, including adding users) and `Bible administrator` (only the Bibles page). Add people at People > Add user. The server cannot send email, so set each new user's first password yourself and tell them privately.
- Adding a file format (USFM, XML, ...): write a reader class in `ml-service/bible_import/formats.py` (same members as `TabSeparatedReader`: `id`, `name`, `description`, `score`, `read`) and add it to `READERS`. Detection, the preview, the import and the Drupal format list pick it up automatically. Add tests in `ml-service/tests/test_bible_import.py`.
- The Drupal module has no automated tests yet (PHPUnit is not set up); the Python side does.

## Show in Context
- Each verse in a result from a Bible stored on this site has four links, "Show in Context", "Full Chapter", "Other Translations" and "Related Verses". Each replaces the result list with a window and an X (or Escape) that goes back to the same results. The first two highlight the chosen verse (search words in bold only there). Show in Context shows some verses before and after it in reading order, with chapter headings when it crosses a chapter. Full Chapter shows the whole chapter that contains the verse and ignores the numbers below. Other Translations lists the same verse in every published Bible stored on this site (the one searched comes first, marked "This result"); a Bible that lacks that verse is left out. Results from the licensed Bibles (NIV, NASB, The Message) have no link: it would cost API.Bible requests and the text would have to be split into verses.
- The window stops at the start and end of the book. How many verses come before and after is set in Drupal at https://cms.bible-and-beyond.com/admin/bibles/settings (defaults 5 before and 10 after, each 0 to 50), together with how many related verses to list (default 10, 1 to 50). They live in the `site_settings` table (migration 002), so changes apply to the public site at once. Same permission as the Bibles page.
- Code: `GET /context`, `GET /chapter`, `GET /parallel` and `GET /related` in `ml-service/main.py` and `ml-service/context.py`; settings in `ml-service/site_settings.py` and `scripts/manage_settings.py` (JSON, used by Drupal); frontend `ContextWindow.tsx` and `SearchResults.tsx`.

## Related Verses (cross references)
- Data: OpenBible.info's cross references (https://www.openbible.info/labs/cross-references/), **licensed CC BY 4.0**, based mainly on the Treasury of Scripture Knowledge (public domain). The license requires credit, which the Related Verses window and the "Bible copyright notices" page give (`frontend/src/CrossReferenceCredit.tsx`). It says the data was reformatted and that links with no positive votes were left out; keep that true if the import changes.
- It lives in the `cross_references` table (migration 003; about 341,000 rows, 42 MB), numbered like the KJV and not tied to one translation. A reference points at a verse or a range. Votes are OpenBible.info users' ranking of how useful a link is; rows with zero or negative votes are not loaded.
- Load or refresh it by hand (the deploy script only warns when the table is empty): download `cross-references.zip` from the page above, unzip it, then run `ml-service/.venv/bin/python ml-service/scripts/import_cross_references.py cross_references.txt` (`--dry-run` first). It replaces every row in one transaction. Its first line carries the release date; the one loaded on 2026-11-06 was dated 2026-11-02.
- `GET /related?translation=&book=&chapter=&verse=` lists the best-voted references first, with their text in the Bible searched, a range expanded to at most 15 verses, and a reference to a verse that Bible lacks shown without text. Only Bibles stored on this site get the link; the licensed Bibles do not.
- The window has two tabs: "Points to" (where the verse points) and "Pointed to by" (`direction=to`: the verses that have a reference beginning at it, or a range inside its chapter that contains it; a range that starts in an earlier chapter and runs through it is not matched). The data is one-way, only 25% of pairs also appear in reverse, so "Pointed to by" is a real second list (John 3:16 points to 23 verses and is pointed to by 104). Migration 004 adds the index for it.
- Each related verse has its own "Show in Context" and "Related Verses" links. They open another window on top, so you can follow a chain of references; Back goes up one level and the X or Escape closes them all and returns to the results (`WindowView` stack in `SearchResults.tsx`, `RelatedPanel.tsx`).

## Original Words (Hebrew and Greek, Strong's lexicon)
- Data: STEPBible-Data (https://github.com/STEPBible/STEPBible-Data) from STEP Bible and Tyndale House, Cambridge, **licensed CC BY 4.0**. Its README and file headers allow including the data in software without asking permission and require credit to "STEP Bible" with a link; they ask people not to post copies of the data files elsewhere. So: the files are never committed (the repository is public; `ml-service/data/stepbible/` is git-ignored), the site offers no download of them, and the API only returns the entries for one verse or one word at a time. Credit is in `frontend/src/StepBibleCredit.tsx`, shown in the Original Words and lexicon windows and on the "Bible copyright notices" page. It says the data was reformatted and that only the Greek words of the modern critical text (NA27/28) are loaded; keep that true if the import changes.
- Tables (migration 005): `original_words` (about 441,000 rows: book, chapter, verse, position, original text, transliteration, English, Strong's number, grammar) and `lexicon_entries` (about 22,700 rows). Verses are numbered like the KJV (TAHOT gives that first, with the Hebrew numbering in brackets), not tied to one translation.
- Load or refresh it by hand (the deploy script only warns when `original_words` is empty): download these into one folder, for example `ml-service/data/stepbible/`: the four TAHOT files and the two TAGNT files from "Translators Amalgamated OT+NT", and TBESH and TBESG from "Lexicons" (names may be shortened but must start with tahot, tagnt, tbesh or tbesg). Then run `ml-service/.venv/bin/python ml-service/scripts/import_original_words.py <folder>` (`--dry-run` first). It replaces every row in one transaction. Loaded on 2026-11-06 from the files on GitHub that day (441,490 words, 22,717 lexicon entries).
- Hebrew words come from the Leningrad reading only (type `L`); a joined word such as `H9003/{H7225G}` keeps the number in braces. Greek words are those whose type starts with N (NA27/28); words found only in the Textus Receptus (such as John 7:53 to 8:11) have none. A few tags carry a sense letter the lexicon lacks (H0430J, G2453); they fall back to the "G" entry of the same number (`resolve_strong_code`).
- `GET /original-words?book=&chapter=&verse=` (the words of a verse, each with its lexicon gloss, 404 when none) and `GET /lexicon?translation=&strong_code=` (an entry, the number of verses that use the word, and the first 30 in Bible order with their text in the Bible searched; licensed Bibles get 422). Code: `ml-service/original_words.py`; frontend `WordsPanel.tsx`, `LexiconPanel.tsx`, and the "Original Words" link in `SearchResults.tsx`. Each lexicon verse has "Show in Context" and "Original Words" links, so the windows chain like Related Verses. Only Bibles stored on this site get the link.
- Search by Strong's number: a search box query that is only a number (`G25`, `g0025`, `H7225`, `H7225G`; letters and spaces forgiven, parsed by `parse_strong_query` in `ml-service/search.py`) lists the verses that contain that Hebrew or Greek word, in the Bibles chosen, with the usual book filter, sorting and paging (the match options do not apply and nothing is bolded). A number without a sense letter also matches its senses (H7225 covers H7225G and the others); a letter narrows it (H7225G only). The response adds `strong` (the lexicon entry chosen: the number itself, else its "G" sense, else the first) and the page shows a note under the heading with an "Open the lexicon entry" link (`openLexicon` in `SearchResults.tsx`; it opens the same lexicon window as a Strong's number in Original Words, with the first Bible searched for the verse text). A number that is not in the lexicon gives a 422 message; the licensed Bibles refuse it (422). A real English search that happens to look like a number (for example "H1") is treated as a Strong's search.
- Click an English word (Berean Standard Bible only): in the Show in Context and Full Chapter windows, the words of a BSB verse are buttons that open the lexicon entry of the Hebrew or Greek word behind them (a hint line says so; Back returns to the passage). Data: the Berean Bible's translation tables, `bsb_tables.tsv` (https://bereanbible.com/bsb_tables.tsv, about 85 MB), **public domain** (the Berean texts were placed in the public domain on 2023-04-30), so no credit is required. The file is git-ignored (`ml-service/data/bsb_tables.tsv`). It lists every original word with its Strong's number and the BSB English for it, in English order. We do not rebuild verses from it (spacing and punctuation differ); `ml-service/word_links.py` walks its English words in order and matches them to the words of our stored text, and a verse gets links only if every table word is found in order (on 2026-11-06: 31,082 of 31,086 verses, 719,917 linked words). Links are stored in `verse_word_links` (migration 006) as `[start, end, "H7225"]` over the verse text, with the md5 of the text they were made for; the lookup ignores them if the verse text has changed, so **run the loader again after re-importing the BSB**: `ml-service/.venv/bin/python ml-service/scripts/import_word_links.py ml-service/data/bsb_tables.tsv` (`--dry-run` first; the deploy script warns when the table is empty). The numbers are plain Strong's numbers ("H7225"); `/lexicon` accepts them and gives the main entry with the verses of every sense. Common words such as "the" and "and" are linked too, to what the table says they translate. The buttons are out of the tab order (hundreds per chapter); keyboard users use the Original Words window, which lists the same numbers. Not done: other Bibles (a public-domain Bible with Strong's numbers, such as the KJV, would need its own data), and the result rows themselves (only the two reading windows have clickable words).

## Commentaries (public domain)
- Six commentaries, each marked **Public Domain** (https://creativecommons.org/publicdomain/mark/1.0/) by the Free Use Bible API (https://bible.helloao.org, AO Lab; its code is MIT, and it serves one JSON file per chapter at `/api/c/<id>/<BOOK>/<chapter>.json`): Matthew Henry, John Gill, Adam Clarke, Jamieson-Fausset-Brown, John Calvin, and Keil and Delitzsch (Old Testament only). Its seventh, the Tyndale Open Study Notes, is CC BY-SA, not public domain, and is not used. The credit is a courtesy (`frontend/src/CommentaryCredit.tsx`: in the window and on the "Bible copyright notices" page). The texts are the old editions as converted by that project, so spelling, wording and the odd conversion flaw are theirs.
- Tables (migrations 007 and 008): `commentaries` (id, names, tab order), `commentary_entries` (book, chapter, verse, end_verse, text; about 78,000 rows, 134 MB) and `commentary_introductions` (book introductions are chapter 0). Verses are numbered like the KJV. An entry covers `verse` to `end_verse`; NULL means to the end of its chapter. Gill, Clarke and Jamieson-Fausset-Brown comment verse by verse and skip some verses; Henry, Calvin and Keil and Delitzsch comment on sections, so an entry runs from its verse to the next entry (`COMMENTARIES` in `ml-service/commentaries.py` says which is which).
- Download and load by hand (the deploy script only warns when `commentary_entries` is empty). The files are git-ignored (`ml-service/data/commentaries/`, about 245 MB): `ml-service/.venv/bin/python ml-service/scripts/download_commentaries.py ml-service/data/commentaries` (about 6,000 files, a few minutes, four connections at a time, can be stopped and rerun; a few chapters do not exist on the host and are skipped), then `ml-service/.venv/bin/python ml-service/scripts/import_commentaries.py ml-service/data/commentaries` (`--dry-run` first; replaces each commentary in one transaction; name commentaries after the folder to load only some). Downloaded and loaded on 2026-11-06: 78,000 entries. To put the files on the server, send a compressed tar of the folder with `scp` (not committed).
- `GET /commentaries?book=&chapter=&verse=&commentary=` lists the commentaries that have notes on the verse (with the verses each note covers) and gives the text of the one asked for, else the first, with its chapter and book introductions; 404 when none has notes. Frontend: `CommentaryPanel.tsx` (one tab per commentary, introductions in expandable sections), the "Commentaries" link in `SearchResults.tsx`. Only Bibles stored on this site get the link (the verse reference is all it needs, but the licensed Bibles have no per-verse links).
- Search inside the commentaries: a second tab, "Search the commentaries" (`SearchTab.tsx` runs one tab each for the Bibles and the commentaries, each keeping its own query and results; `SearchForm.tsx` and `SearchResults.tsx` serve both through a `mode`). The form offers match all words, any word or exact phrase, one commentary or all, and the same book filters; whole words and the Bible list do not apply. `GET /search-commentaries?query=&match_mode=&commentary=&book_start=&book_end=&book=&page=&per_page=&sort_by=verse&sort_direction=` (code in `ml-service/commentaries.py`, `search_commentaries`) returns the same shape as `/search` with `source: "commentary"`, one result per note: `reference` is the verses the note covers, `commentary_id`/`commentary_name`, and `text` is an excerpt around the words found, with each found word wrapped in the control characters U+0001 and U+0002 (the page turns them into bold type). `GET /commentary-list` lists the commentaries (the tab appears only when there are some). Results are best match first (`ts_rank_cd`) unless sorted by verse (the "Verse" heading; Clear Sort goes back). Each result links to "Read the note" (the Commentaries window on that commentary, with the search words in bold) and "Show in Context" (in the BSB, else the first Bible here).
- How the matching works (migration 008): a stored `search_vector` column and a GIN index on `commentary_entries`, built with our own text search configuration `commentary_english` (English word forms, so love finds loved and loving, but **without** Postgres's list of ignored common words, so "born again" or "so loved the world" match exactly; the stock `english` configuration would drop "again", "so" and "the"). Words are not matched as parts of words (the Bible search matches inside words; this one does not), and a Bible-style "whole words" option does not apply. Adding the column recomputes every row (about 20 seconds on a laptop, longer and blocking reads of that table on the server) and adds about 180 MB with the index (the database was 361 MB before it). `import_commentaries.py` needs nothing extra: the column is generated. An excerpt is built only for the 25 or so notes on the page (it reads the whole note). Slowest case seen: a search for only common words ("the of and") about 0.5 s.
- References inside a note are links: `ml-service/scripture_references.py` finds `Book chapter:verse` (and a range `3:16-18`, linked to its first verse) in the note and in its chapter and book introductions, and `GET /commentaries` returns them as `references`, `chapter_introduction_references` and `book_introduction_references`, each `[start, end, "book:chapter:verse"]` over the text it belongs to. It accepts a book name written in capitals too (`PHI. 3:13`, `DEUT. 31:8`, as Daily Light writes them) but not a lower-case one (`job 3:4`). **A bug fixed on 2026-11-06:** after the short two-letter codes were added (`Sa`, `Ki`, `Co`...), `Isa` and `I Sa` (1 Samuel) became the same lookup key, so every `Isa 53:5` in the commentaries was linked to 1 Samuel (or dropped when 1 Samuel had no such chapter); the lookup key now keeps the space after a Roman numeral and a plain name wins a clash (`test_isaiah_is_not_taken_for_first_samuel`, `test_no_two_books_share_a_name`). It knows both spellings the six commentaries use (the short CCEL codes Psa, Kg1, Co1, Jo1, Joh, Zac, Jde, Plm and number-first forms such as 2Ki. and 1Co. in Henry, Clarke, Jamieson-Fausset-Brown and Keil and Delitzsch; the full names Psalm, 1 Kings, Song of Solomon in Gill and Calvin) and roman numerals (I John). It links only a reference that names a verse that exists, checked against the chapter lengths of the Bible with the most verses (`verse_limits`, kept for an hour); a reference to a verse that does not exist in that numbering is left plain (mostly Psalms, whose Hebrew numbering counts the title line, about 140 in all). Not linked: lists that leave the book out ("Joh 3:16, 17"), chapter-only references, the Apocrypha (Maccabees, Sirach, Tobit, Wisdom, which our Bibles do not have), and a range that runs into the next chapter beyond its first verse. On 2026-11-06 it found 270,175 references in the 77,984 notes (about 99.6% of everything shaped like a reference); the longest note, 93,000 characters, takes about 13 ms. A reference opens "Show in Context" for its first verse in the Bible of the window, on top of the note; Back returns to the same note and tab. The reference buttons are in the tab order (unlike Strong's links), and `highlightLinked` in `highlight.tsx` takes `LinkOptions` for either kind.
- Browsing without a search (third tab, "Browse the commentaries", `BrowseTab.tsx`): choose a commentary, then a book, a chapter and optionally a verse and press Go (the book and chapter choosers act at once; the commentary chooser keeps the same place, and the verse when the reader is still on its chapter, so one passage can be compared across commentaries; a commentary without that book, such as Keil and Delitzsch for the New Testament, starts at its first). The page scrolls to the note that covers the verse (marked with a bar), and the reader can **scroll on past it in both directions**: chapters load above and below as the ends come near, across book boundaries, up to 9 chapters kept at once (far ones are dropped), and the book and chapter choosers follow the chapter at the top of the screen. Each note has "Show in Context" and "Other Commentaries" links, and its references are links (the same windows as in search; opening one hides the reading, and closing it puts the page back at the same scroll position and the link back in focus). The choosers stay at the top of the screen on wide windows and scroll away on phones. API: `GET /commentary-contents?commentary=` (books and the chapters with notes, for the choosers) and `GET /commentary-chapter?commentary=&book=&chapter=` (every note of the chapter in verse order with what each covers and its references, both introductions, and the `previous` and `next` chapters with notes across books; 404 when there are no notes). The largest chapter is 337,000 characters (Calvin on Psalm 119). The tab loads only when first opened. Getting back to the tabs (the top of the page): because chapters keep loading above the reader (and the reader's place is held while they do), the browser's own jump to the top never arrives, so the tab has its own: the Home key (also Ctrl+Home and Cmd+Up Arrow; not while typing in the verse box or a chooser), a bold blue floating "↑ Back to tabs" button that appears after about a screenful of scrolling, a "↑ Back to tabs" link at the right of the choosers (always in view on wide windows) and another under the last loaded chapter. Clicking any tab also scrolls to the top. (The first version labelled the floating button "↑ Top" in a small grey pill and was not noticed; keep it obvious.) Each calls `scrollToTop` from `useChapterStrip`, which also stops chapters being added above until the reader has scrolled about 800 px down again (otherwise they would carry the page away from the top).
- Shared parts of the two readers (the commentary browser and the Bible reader): `useChapterStrip.ts` is the continuous-scroll engine, independent of what is read (it needs a `load(book, chapter, signal)` returning a chapter with `previous` and `next` neighbours; it keeps the reader's place when chapters are added above, loads ahead with an IntersectionObserver and tracks the chapter on screen); `useVerseWindows.ts` holds the window stack that the search results and both readers use; `useReaderWindows.ts` adds the scroll save and restore around it; `useBackToTabs.ts` and `BackToTabs.tsx` are the Home key and the floating button; `NoteText.tsx` draws commentary text with reference links. The reader tabs reuse the `.browse-*` styles.
- Not built: highlighting word forms in the note itself (the note shows the words as typed in bold; the excerpt shows the forms found), and links from other places into the reader (for example a "Read the whole chapter" link in the Commentaries window). Possible next steps for references: lists that omit the book, and a choice between Show in Context and Commentaries for a clicked reference.

## Reading the Bible (first tab)
- "Read the Bible" is the first tab and the one that opens by default (`BibleTab.tsx`). It reads a Bible stored on this site (ASV, BSB, KJV, WEB, YLT, anything published; the licensed Bibles NIV, NASB and The Message cannot be read this way because they are never stored): choose a Bible, a book, a chapter and optionally a verse and press Go. The page goes to the verse (marked with a bar) and the reader can scroll on past it in both directions, chapter after chapter and book after book, exactly like the commentary browser (same engine, `useChapterStrip`; up to 9 chapters kept; the choosers follow the chapter at the top; the back-to-tabs controls and the Home key work the same). The BSB opens at Genesis 1 the first time. Changing the Bible keeps the place and the verse (while the reader is still on its chapter); a Bible without that book starts at its first.
- A verse has a menu with the same six things as the links of a search result: Show in Context, Full Chapter, Other Translations, Related Verses, Original Words and Commentaries (`verseMenuItems` in `BibleTab.tsx`, drawn by `VerseMenu.tsx`). Right-click a verse, or click or tap its number (the number is a button, so it also works from the keyboard and on a phone; the menu key or Shift+F10 on it opens the menu too). The menu opens at the pointer, stays inside the window, moves with the arrow keys, Home and End, chooses with Enter, and closes with Escape, a click elsewhere or any scroll. It does not replace the browser's own menu when text is selected or Shift is held, so copying still works. The first version showed the six links under every verse and was found cluttered; do not bring them back. The chosen verse is tinted while the menu is open. The windows open over the reading as before; closing one puts the page back at the same scroll position and the focus back on the verse number. (Full Chapter repeats what the page shows; it is there because it was asked for, and is one line to remove.) In the BSB the words are also clickable (Strong's numbers, as in Show in Context); the other Bibles are plain text. A hint line above the reading says how to open the menu. Verses sit on consecutive lines with no space between them (a verse is one line or a few wrapped lines; the reading is not run together as a paragraph).
- API (`ml-service/bible_reader.py`): `GET /bible-contents?translation=` (books and chapters of a Bible, for the choosers) and `GET /bible-chapter?translation=&book=&chapter=` (every verse of the chapter with `links` where the Bible has them, and the `previous` and `next` chapters across books). Licensed codes give 422; an unknown or hidden Bible, or a chapter it lacks, gives 404. The code can be written in any case.
- Not built: reading the licensed Bibles (it would cost API.Bible requests per chapter and the terms need the copyright notice and usage reporting), a choice of the Bible text next to a second Bible side by side, and word links for Bibles other than the BSB.

## Devotionals (Devotionals tab)
- Four public-domain devotionals, in one reader tab ("Devotionals", the last tab; it appears only when the table has data): Spurgeon's **Morning and Evening** and **Daily Light on the Daily Path** (a morning and an evening reading for each of 366 days, February 29 included) and **The Imitation of Christ** (William Benham's 1886 translation; 4 books, 25 + 12 + 59 + 18 = 114 chapters) and **The Practice of the Presence of God** (a preface, 4 conversations, 15 letters). Code: `ml-service/devotionals.py`, `DevotionalsTab.tsx`; tables in migration 009 (`devotionals`, `devotional_sections`, `devotional_entries`). A devotional is sections (months, or books and parts) of units (days, or chapters); `kind` is `daily` or `chapters`.
- **Sources and licence.** Morning and Evening and Daily Light come from the Christian Classics Ethereal Library's ThML files (https://ccel.org/ccel/spurgeon/morneve and https://ccel.org/ccel/anonymous/daily_light; each file's header says `DC.Rights: Public Domain`; Spurgeon wrote it in 1865 and Daily Light is from the 1800s). **CCEL's own copyright policy (https://www.ccel.org/about/copyright.html) says its editions rest on books that are public domain in the United States, may have copyrighted introductions and special contents, "may be used for personal, educational, or non-profit purposes", and asks people to contact them to republish its works or use them commercially.** This site is non-commercial and uses only the text of the two books, with credit, and the files are not committed or offered for download; but it is worth asking CCEL for permission (see Open items). The Imitation (Project Gutenberg eBook #1653) and the Practice (#13871) are Gutenberg texts of 19th-century translations. **Do not use Gutenberg #5657 for the Practice: it is marked "COPYRIGHTED Project Gutenberg eBook".** CCEL's own Imitation is the 1940 Bruce translation (renewal not found, but newer); Benham's 1886 is used instead. The credit is `DevotionalCredit.tsx`, under each reading and on the "Bible copyright notices" page.
- Load by hand (the deploy script only warns when `devotional_entries` is empty); the files are git-ignored (`ml-service/data/devotionals/`, about 5 MB): `ml-service/.venv/bin/python ml-service/scripts/download_devotionals.py ml-service/data/devotionals`, then `ml-service/.venv/bin/python ml-service/scripts/import_devotionals.py ml-service/data/devotionals` (`--dry-run` first; replaces each devotional in one transaction; a file whose number of days or chapters is wrong is refused). The XML is read with `defusedxml` (in `requirements.txt`), because the files come from outside. Loaded on 2026-11-06: 732 + 732 + 114 + 20 entries.
- How they are read: the ThML books have one `div2` per reading (`Morning, January 1`), with the key verse, a line naming it, and paragraphs; Daily Light's lines of references (`John 17:24. -II Tim. 1:12. -Phi. 1:6.I Cor. 9:24,25.`) are tidied into one line per group, joined with semicolons. The Gutenberg books are read by their headings (the Imitation's contents list at the top repeats every heading, so the book is taken from the last "THE FIRST BOOK"); hard-wrapped lines are joined into paragraphs and Gutenberg's `_italic_` marks are dropped. Each text's footnotes stay at the end of its chapter.
- API: `GET /devotionals` (the list, in tab order), `GET /devotional-contents?devotional=` (sections and their days or chapters, for the choosers) and `GET /devotional-unit?devotional=&section=&unit=` (one day or chapter: its entries, each with the scripture references found in it, and the `previous` and `next` days or chapters across months and parts). The scripture references are linked like those in commentaries (a click opens the verse in context, in the BSB). The reader is the same engine as the Bible reader and the commentary browser (`useChapterStrip`, with a section as its "book" and a day or chapter as its "chapter"): choose a devotional, a month and day (or a part and chapter), scroll on in both directions, Today (daily ones open at today's date; the day is kept when switching between the two daily books), the back-to-tabs controls and Home. 
- Not built: searching the devotionals, a way to follow one chapter of the Imitation by its Latin numbering, and reading plans or bookmarks.

## Deploying
- Push to `main`, then run `deploy/deploy.sh` from your Mac (`--all` rebuilds and restarts everything). It pulls on the server, then only redoes what changed: Python dependencies and an ML service restart, the frontend build (`VITE_ML_SERVICE_URL=/api`), Composer, Drupal database updates and a cache rebuild. It then checks health, including from outside. The server deploys what is on GitHub, not your working copy.
- It unlocks Drupal's read-only settings folder only while git updates files, and locks it again afterwards (`555`, not `444`, because git tracks `settings.php` as executable).
- nginx and PHP-FPM config files need sudo, so the deploy script only reports when the installed copies differ from `deploy/`. Install them with `ssh -t bible-and-beyond sudo ~/bible-and-beyond.com/deploy/install-system-config.sh`. It replaces only changed files, tests the configuration, and puts the old files back if the test fails.
- Make changes in the repository and deploy them. Do not edit files on the server; that blocks `git pull`.
